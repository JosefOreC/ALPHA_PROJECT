## 2. Marco de Elicitación Holística y Ética

### 2.1 Contexto del proceso de recolección de necesidades

El proceso de elicitación de requisitos para el sistema EcoLogística Lima se llevó a cabo considerando la diversidad de perfiles que interactúan con la cadena logística de última milla en los distritos de San Juan de Lurigancho, El Agustino, Santa Anita y Ate, dentro del corredor logístico de Lima Este.

La recolección de necesidades se orientó bajo tres ejes transversales:

- **Contexto local (glocal):** Se reconoció que los patrones de tráfico, las ventanas de entrega y las restricciones viales en Lima Este difieren significativamente de estándares internacionales. Las restricciones vehiculares municipales, el estado de las vías y los horarios de mayor congestión fueron insumos directos del proceso.
- **Diversidad de grupos de usuarios:** Se identificaron conductores de reparto (con variada alfabetización digital), operadores de logística, administradores del sistema y auditores externos. Los requisitos fueron validados considerando las capacidades reales de cada grupo.
- **Perspectiva ética:** Se incorporó la Ley N.° 29733 (Protección de Datos Personales) como restricción no negociable en el tratamiento de datos de conductores y destinatarios. Asimismo, se aplicó el principio de minimización de datos: el sistema solo recolecta la información estrictamente necesaria para la operación.

## 3. Especificación Atómica de Requisitos Funcionales

---

### RF-001: Gestión de Flota Vehicular

- **Descripción Atómica:** El sistema debe permitir registrar, editar y consultar los vehículos de la flota de DistriRápido S.A.C. cuando un usuario con rol Administrador u Operador accede al módulo de flota.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el usuario está autenticado con rol Administrador u Operador
CUANDO ingresa los datos completos y válidos de un vehículo nuevo (placa, capacidad, tipo de combustible, estado)
ENTONCES el sistema registra el vehículo, lo asocia a la flota activa y confirma el registro con un mensaje de éxito

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que el usuario tiene rol Operador
CUANDO consulta la lista de vehículos disponibles sin modificar ningún registro
ENTONCES el sistema muestra el listado actualizado con estado y disponibilidad de cada vehículo

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que el usuario intenta registrar un vehículo con una placa ya existente en el sistema
CUANDO envía el formulario de registro
ENTONCES el sistema rechaza la operación, mantiene el estado consistente de la base de datos y despliega el mensaje: "La placa ingresada ya se encuentra registrada en el sistema"
```

### RF-002: Gestión de Pedidos

- **Descripción Atómica:** El sistema debe permitir registrar, consultar y actualizar el estado de pedidos de entrega cuando un usuario con rol Operador o Conductor accede al módulo de pedidos.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el Operador está autenticado y accede al módulo de pedidos
CUANDO ingresa un nuevo pedido con dirección de destino, ventana horaria y peso del paquete
ENTONCES el sistema registra el pedido con un identificador único, lo vincula a la zona geográfica correspondiente y lo deja disponible para ser asignado a una ruta

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que el Conductor accede a su lista de pedidos asignados
CUANDO marca un pedido como entregado exitosamente
ENTONCES el sistema actualiza el estado del pedido a "Entregado" y registra la hora de confirmación

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que se intenta registrar un pedido con una dirección fuera de la zona de cobertura del sistema
CUANDO el Operador envía el formulario
ENTONCES el sistema rechaza el pedido y despliega: "La dirección indicada está fuera del área de cobertura operativa"
```

---

### RF-003: Generación de Rutas Optimizadas

- **Descripción Atómica:** El sistema debe calcular y generar rutas de reparto optimizadas considerando ventanas de tiempo, capacidad vehicular, emisiones de CO₂ y datos de tráfico en tiempo real, cuando el Operador ejecuta la planificación diaria.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el Operador tiene al menos un pedido pendiente y al menos un vehículo disponible
CUANDO ejecuta la acción de generar rutas para el día operativo
ENTONCES el sistema calcula y retorna rutas optimizadas para hasta 150 pedidos y 15 vehículos en un tiempo máximo de 45 segundos, respetando las ventanas de entrega de cada pedido

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que el volumen de pedidos es menor a 150 y hay suficientes vehículos disponibles
CUANDO el sistema ejecuta el algoritmo de optimización
ENTONCES las rutas generadas minimizan las emisiones de CO₂ como función objetivo secundaria, priorizando el cumplimiento de ventanas de tiempo

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que no hay vehículos disponibles en la flota activa
CUANDO el Operador intenta generar rutas
ENTONCES el sistema no ejecuta el algoritmo, mantiene el estado consistente y despliega: "No hay vehículos disponibles para generar rutas en este momento"
```

---

### RF-004: Visualización de Rutas en Mapa

- **Descripción Atómica:** El sistema debe mostrar en un mapa interactivo las rutas asignadas, la ubicación de los vehículos y el estado de los pedidos en tiempo real, cuando un usuario con rol Operador o Administrador accede al módulo de mapa.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el Operador accede al módulo de mapa y existen rutas generadas para el día
CUANDO el mapa carga completamente
ENTONCES el sistema muestra todas las rutas activas con sus paradas, el estado de cada pedido (pendiente, en camino, entregado) y la posición actualizada de cada vehículo sobre la cartografía de Lima Este

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que el Operador selecciona un vehículo específico en el mapa
CUANDO hace clic sobre el ícono del vehículo
ENTONCES el sistema despliega un panel lateral con los detalles de la ruta asignada, los pedidos pendientes y el tiempo estimado de arribo a la siguiente parada

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que la fuente de datos cartográficos (OpenStreetMap / Leaflet) no está disponible
CUANDO el usuario accede al módulo de mapa
ENTONCES el sistema despliega un mensaje de indisponibilidad temporal del mapa y ofrece la vista alternativa en lista de rutas
```

---

### RF-005: Dashboard de Indicadores Operativos

- **Descripción Atómica:** El sistema debe mostrar un panel de control con los indicadores operativos clave del día (pedidos entregados, tasa de cumplimiento de ventanas, kilómetros recorridos, emisiones de CO₂ acumuladas), cuando un usuario con rol Administrador u Operador accede al módulo de dashboard.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el Administrador accede al dashboard en horario operativo
CUANDO el panel carga
ENTONCES el sistema muestra en tiempo real: total de pedidos entregados vs. pendientes, porcentaje de cumplimiento de ventanas horarias, kilómetros totales recorridos por la flota y toneladas de CO₂ emitidas en el día

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que el Operador accede al dashboard con filtro por zona geográfica
CUANDO aplica el filtro de distrito
ENTONCES el sistema actualiza todos los indicadores mostrando únicamente los datos del distrito seleccionado

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que no hay datos operativos del día actual (primer acceso del día sin rutas generadas)
CUANDO el usuario carga el dashboard
ENTONCES el sistema muestra el panel con valores en cero e indica: "No se han generado rutas para la jornada actual"
```

---

### RF-006: Reportes de Sostenibilidad

- **Descripción Atómica:** El sistema debe generar reportes de sostenibilidad exportables que incluyan métricas de emisiones de CO₂, consumo de combustible y eficiencia de rutas por período, cuando un usuario con rol Administrador accede al módulo de reportes.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el Administrador selecciona un rango de fechas y el tipo de reporte "Sostenibilidad"
CUANDO ejecuta la generación del reporte
ENTONCES el sistema procesa la solicitud en un máximo de 1.5 segundos (P95) y entrega un archivo exportable con las métricas de CO₂ (kg), combustible (litros), kilómetros recorridos y número de entregas completadas en el período

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que el Administrador genera el reporte en formato CSV
CUANDO descarga el archivo
ENTONCES el sistema entrega un CSV correctamente estructurado con encabezados en español y separadores compatibles

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que el rango de fechas seleccionado no contiene datos registrados
CUANDO el Administrador ejecuta la generación
ENTONCES el sistema no genera un archivo vacío sino que despliega: "No se encontraron registros operativos para el período seleccionado"
```

---

### RF-007: Gestión de Conductores

- **Descripción Atómica:** El sistema debe permitir registrar, editar, activar y desactivar perfiles de conductores vinculados a la flota, cuando un usuario con rol Administrador accede al módulo de gestión de conductores.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

```gherkin
#### Ruta Gold (Camino Ideal Principal)
DADO que el Administrador accede al módulo de conductores
CUANDO registra un nuevo conductor con nombre, DNI, licencia de conducir y vehículo asignado
ENTONCES el sistema crea el perfil del conductor, lo vincula al vehículo correspondiente y lo deja disponible para asignación de rutas

#### Ruta Feliz (Flujo Alternativo Válido)
DADO que un conductor se encuentra temporalmente inactivo
CUANDO el Administrador cambia su estado a "Inactivo"
ENTONCES el sistema desvincula al conductor de rutas futuras sin eliminar su historial operativo

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que se intenta registrar un conductor con un DNI ya existente en el sistema
CUANDO el Administrador envía el formulario
ENTONCES el sistema rechaza el registro y despliega: "El DNI ingresado ya corresponde a un conductor registrado en el sistema"
```
