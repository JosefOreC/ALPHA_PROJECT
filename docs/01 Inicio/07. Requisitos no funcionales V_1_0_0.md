## 2. Consideraciones metodológicas

Todos los requisitos no funcionales están definidos mediante **Escenarios de Calidad** bajo el esquema: `Fuente → Estímulo → Entorno → Artefacto → Respuesta → Medida SLA`. Queda prohibido el uso de adjetivos calificativos sin umbral cuantitativo explícito ("rápido", "seguro", "eficiente").

## 3. Catálogo de Requisitos No Funcionales

| ID | Categoría ISO 25010 | Escenario de Calidad (Fuente → Estímulo → Entorno → Artefacto → Respuesta → Medida SLA) |
| --- | --- | --- |
| **RNF-001** | Rendimiento | **Fuente:** Operador del sistema. **Estímulo:** Solicitud de generación de rutas para 150 pedidos y 15 vehículos. **Entorno:** Operación normal con carga estándar. **Artefacto:** Módulo de optimización de rutas (algoritmo VRPTW/Green VRP). **Respuesta:** El sistema calcula y retorna el conjunto de rutas optimizadas. **Medida:** Tiempo de respuesta ≤ 45 segundos en el percentil 95 (P₅). |
| **RNF-002** | Seguridad | **Fuente:** Atacante externo. **Estímulo:** Intento de inyección SQL en el endpoint de autenticación. **Entorno:** Producción. **Artefacto:** API Gateway / WAF. **Respuesta:** Bloquear la petición, registrar el evento en el log de auditoría y notificar al equipo de seguridad. **Medida:** 0% de vulnerabilidades críticas OWASP Top 10 ejecutables. Cumplimiento de Ley N.° 29733. |
| **RNF-003** | Disponibilidad | **Fuente:** Infraestructura cloud. **Estímulo:** Caída de un nodo en la zona de disponibilidad primaria. **Entorno:** Operación 24/7 en horario 05:00 – 22:00. **Artefacto:** Clúster de contenedores / Base de datos. **Respuesta:** Failover automático hacia la zona secundaria sin intervención manual. **Medida:** RTO ≤ 30 segundos, RPO ≤ 5 segundos, SLA global ≥ 99.5% anual en horario operativo. |
| **RNF-004** | Rendimiento (Reoptimización) | **Fuente:** Sistema de monitoreo de tráfico. **Estímulo:** Detección de incidencia vial que invalida una ruta activa. **Entorno:** Operación en tiempo real con rutas en curso. **Artefacto:** Módulo de reoptimización dinámica. **Respuesta:** El sistema recalcula la ruta afectada y notifica al conductor. **Medida:** Tiempo de reoptimización ≤ 30 segundos desde la detección del evento. |
| **RNF-005** | Usabilidad / Accesibilidad | **Fuente:** Conductor con baja alfabetización digital. **Estímulo:** Primer uso de la interfaz móvil sin capacitación previa. **Entorno:** Dispositivo móvil con conexión 4G en campo. **Artefacto:** Interfaz del conductor (vista móvil). **Respuesta:** El conductor completa el flujo de confirmación de entrega sin errores. **Medida:** Cumplimiento WCAG 2.1 AA. — *Umbral de tiempo máximo de interacción por tarea: pendiente de definición por el equipo.* |
| **RNF-006** | Escalabilidad | **Fuente:** Crecimiento operativo de DistriRápido S.A.C. **Estímulo:** Incremento de la demanda a 1,000 pedidos diarios y 50 vehículos activos. **Entorno:** Operación con carga ampliada. **Artefacto:** Arquitectura del sistema (backend + base de datos). **Respuesta:** El sistema mantiene los tiempos de respuesta dentro de los umbrales definidos sin rediseño de arquitectura. **Medida:** Degradación de rendimiento ≤ 20% respecto al baseline de 150 pedidos/15 vehículos al escalar al doble de la carga. |

## 4. Requisitos no funcionales pendientes de definición

Los siguientes atributos de calidad requieren decisión del equipo antes de poder formalizarse como escenarios métricos completos:

| ID Tentativo | Categoría | Descripción del pendiente |
| --- | --- | --- |
| RNF-007 | Mantenibilidad | Umbral mínimo de cobertura de pruebas unitarias (e.g., ≥ 80% de cobertura sobre módulos críticos). Definir con el equipo. |
| RNF-008 | Sostenibilidad | Métrica cuantitativa de reducción de emisiones de CO₂ por kilómetro respecto a la línea base (sin optimización). Definir con el equipo. |
| RNF-009 | Usabilidad | Tiempo máximo para que un conductor complete el flujo de confirmación de entrega desde la pantalla principal. Definir con el equipo. |

> **⚠ Pendiente de decisión del equipo:** Completar RNF-007, RNF-008 y RNF-009 con los umbrales SMART correspondientes una vez que el equipo valide los criterios de aceptación mínimos del sistema.
